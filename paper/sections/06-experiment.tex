\section{实验方案}
\label{sec:experiment}

本节给出 DCC-KV 的实验设计、评测协议与结果报告规范。需要首先明确本节的性质：\textbf{本文
尚未报告端到端任务指标与通信性能。}截止撰写时，仓库所实现并已在 CPU 上验证的部分为
（i）紧凑 KV 构造全流程，（ii）在线 Softmax 归并算子的顺序无关性，（iii）同步版分布式
注意力的数值等价性，（iv）变长 All-to-All 消息的打包、解包与接口形状。异步通信流水与多卡
可扩展性依赖 GPU 环境，尚未执行。因此，本节按"已可复现的验证"与"待执行的实验"两类分别
陈述，并给出后者的完整协议，以便结果补齐后可直接填入。

\subsection{实验设置}
\label{sec:exp-setup}

\subsubsection{硬件与软件}

CPU 验证部分在任意多核环境即可复现，无需 GPU。GPU 部分按 \texttt{docs/reproducibility.md}
第 4 节设定的配置执行：M2（多卡同步）最低 2$\times$A100 80G，M3（异步）最低
4$\times$A100 80G NVLink，M4（端到端 8B）推荐 8$\times$A100 80G，70B/72B 与跨节点实验
需要 8$\times$H100 或双节点环境。所有依赖版本通过 \texttt{requirements.lock} 锁定；
PyTorch 版本、CUDA、NCCL 与 Transformers 版本均记入 \texttt{ExperimentMetadata}
（见 \S\ref{sec:exp-metadata}）。

\subsubsection{模型}

评测覆盖四个模型以检验方法对模型族的迁移性：
Llama-3.1-8B-Instruct、Llama-3.1-70B-Instruct、Qwen2.5-72B-Instruct、
Mistral-7B-Instruct-v0.3。前两者为同族不同规模，用于检验规模迁移；Qwen2.5 与 Mistral 为
不同训练语料与架构配置，用于检验跨族迁移。

\subsubsection{数据集}

长上下文任务覆盖检索、问答、多跳推理与长文困惑度四类：
LongBench 与 LongBench-v2（多任务长文理解）、$\infty$Bench（超长文本）、
RULER（合成检索与多跳，可控长度）、Needle-in-a-Haystack（单针检索，长度可控）、
PG-19 与 wikitext-103（语言建模困惑度）。其中 RULER 与 NIAH 的长度可精确控制，
是绘制"误差--上下文长度"曲线的首选。

\subsubsection{基线}

三个基线：Ring Attention（精确序列并行的代表，作为精度上界与性能参照）、
FastKV（共享压缩，即所有目的端复用同一压缩结果，用于隔离"目的端条件化"的贡献）、
APB（全网共享 anchor 的压缩方案）。三者与 DCC-KV 的差异在通信语义上是清晰的：
Ring Attention 不压缩，FastKV 压缩但不条件化，APB 压缩且共享锚点，
DCC-KV 压缩且逐边条件化。

\subsubsection{超参数与随机性}

关键超参数为代表 Query 数 $M$、投影维度 $d_p$、压缩预算 $B_{s,r}$、
正则系数 $\lambda_\beta$ 与 $\lambda_v$。所有实验固定随机种子（默认 42，备选 123 / 1024 / 7），
每个数据点至少重复 10 次，报告 median 与 p5/p95，并给出 bootstrap 95\% 置信区间。
$\beta$ 的校准参数在当前实现中取固定默认值：箱约束 $[-3,3]$ 与
$\lambda_\beta=3\times10^{-2}$，二者均来自源论文所选项的继承或本文的网格定位
（\S\ref{sec:exp-e10}、\S\ref{sec:exp-e11}），不随任务调整。

\subsection{评测协议与元数据规范}
\label{sec:exp-metadata}

为避免"实验条件不可追溯"导致的结论不可复现，每次 run 由 \texttt{ExperimentMetadata}
记录：\texttt{run\_}\allowbreak\texttt{id}、\texttt{git\_}\allowbreak\texttt{commit}、
\texttt{pytorch\_}\allowbreak\texttt{version}、\texttt{model\_}\allowbreak\texttt{name}、
\texttt{context\_}\allowbreak\texttt{length}、\texttt{gpu\_}\allowbreak\texttt{count}、
\texttt{seed}、\texttt{budget\_}\allowbreak\texttt{ratio}、
\texttt{sync\_}\allowbreak\texttt{async}、
\texttt{num\_}\allowbreak\texttt{repr\_}\allowbreak\texttt{queries}、
\texttt{projection\_}\allowbreak\texttt{dim}、
\texttt{lambda\_}\allowbreak\texttt{beta}、\texttt{lambda\_}\allowbreak\texttt{value}、
\texttt{rope\_}\allowbreak\texttt{extension\_}\allowbreak\texttt{used} 与
\texttt{rope\_}\allowbreak\texttt{extension\_}\allowbreak\texttt{disclosed}。

其中后两项的设计值得说明：若为达到目标上下文长度而使用了 RoPE 外推，必须显式披露。这一约束
的目的是防止把"位置编码外推带来的效果"误归因为压缩机制的贡献。凡
\texttt{rope\_}\allowbreak\texttt{extension\_}\allowbreak\texttt{used}
为真而 \texttt{rope\_}\allowbreak\texttt{extension\_}\allowbreak\texttt{disclosed}
为假的 run，其结果不进入主表。

结果聚合由 \texttt{RunResult.from\_values} 完成，统一产出 median、p5/p95 与
bootstrap 95\% CI。该实现意味着所有报告数字必须来自多次 run 的分布，而非单次运行值。

一处口径必须写明，否则表格不可复现：\S\ref{sec:exp-e10} 与 \S\ref{sec:exp-e11} 中
跨格汇总的「中位数」一律是\textbf{上中位数}——把 $n$ 个逐格值升序排列后取第
$\lfloor n/2\rfloor+1$ 小者（$n=180$ 时取第 $91$ 小），与落盘脚本中的
\texttt{\_med} 实现一致。这与 \texttt{statistics.median}（偶数样本取中间两值之平均）
\textbf{不同}：按后者复算同一批 $180$ 格，$\lambda_\beta=10^{-3}$ 的留出归并误差
会得到 $0.432$ 而非表中的 $0.435$。故引用这两节的表格时，须按上中位数复现。

\subsection{已验证的 CPU 实验}
\label{sec:exp-cpu}

以下四组实验对应仓库中已存在的测试，均可在纯 CPU 环境复现。

\subsubsection{E0：顺序无关性}

\textbf{目的}：验证式~(26) 的交换律与结合律在有限精度下成立，即异步乱序归并与顺序归并的
结果差异处于浮点舍入量级。

\textbf{方法}：构造 $K$ 个随机块（长度与 $d_v$ 各异），各自生成在线 Softmax 状态，然后
（i）按原顺序归并，（ii）随机置换后归并，（iii）按树形分组归并，比较三者输出。

\textbf{已有证据}：\texttt{verify\_order\_invariance} 在 $K=8$、20 次随机试验下返回真；
\texttt{test\_order\_invariance} 与 \texttt{test\_merge\_two\_states} 通过，两状态归并与
单次 dense 计算的差异在 \texttt{FP64} 下低于 $10^{-6}$。

\textbf{待补}：需把"置换数量"与"归并树形状"作为自变量，报告最大相对误差随二者的变化曲线，
以界定异步实现的数值安全边界。

\subsubsection{E1：紧凑 KV 构造的接口与形状不变量}

\textbf{目的}：确认 $C_k^{s\to r}$、$\beta^{s\to r}$、$C_v^{s\to r}$ 的形状与预算约束一致，
且随机构造可复现。

\textbf{已有证据}：\texttt{build\_compact\_kv} 在 $B=64$、$d_h=d_v=32$ 下返回
\texttt{keys} $(64,32)$、\texttt{logit\_bias} $(64,)$、\texttt{values} $(64,32)$、
\texttt{selected\_indices} $(64,)$；Top-$B$ 选择返回的索引互不重复；
相同种子下代表 Query 选择完全一致。

\subsubsection{E2：压缩保真度}

\textbf{目的}：测量 $\epsilon_{\text{mass}}$ 与 $\epsilon_{\text{out}}$ 在受控压缩比下的
经验分布。

\textbf{方法}：固定 $L=256$、$d_h=d_v=32$、$\mathrm{FP64}$，扫描
$B \in \{8, 16, 32, 64, 128\}$，对每个 $B$ 计算紧凑块与完整块在代表 Query 上的
质量误差与输出误差，并与 Dense 全注意力对比。

{\sloppy
\textbf{关于既有测试的一处更正}：本文早期版本曾引用
\texttt{test\_fast\_kv\_}\allowbreak\texttt{vs\_dense\_}\allowbreak\texttt{within\_tolerance}
（$B=64$ 时偏差 $<0.1$）与

\textbf{已补}：$\epsilon_{\mathrm{mass}}(B)$ 与 $\epsilon_{\mathrm{out}}(B)$ 的完整曲线
已在 \texttt{experiments/}\allowbreak\texttt{cpu/}\allowbreak
\texttt{e2\_fidelity\_}\allowbreak\texttt{curve.py} 中实现并运行。两条实测结论：
（i）$\epsilon_{\mathrm{out}}(B)$ 随预算增大\emph{并非单调下降}；
（ii）RMS 排序选出的 Key 恰是高权重位置，实际保留的注意力质量显著高于名义预算比
$B/L$——在 $B/L=0.031$ 时实测保留 $0.291$（$9.32$ 倍），在 $B/L=0.5$ 时保留 $0.919$。
名义压缩比因此系统性低估了信息保留率，这一点在解释"为何压到 3\% 仍可用"时是关键。

\textbf{一处度量更正}：$\epsilon_{\mathrm{mass}}$ 的早期实现（及本节的早期版本）
采用"两侧各自减去自身最大值"的做法。该做法对 $\beta$ 的\emph{常数分量完全免疫}——
而常数分量恰是 $\beta$ 的主要职责。已在
\texttt{experiments/}\allowbreak\texttt{common/}\allowbreak
\texttt{synthetic.py} 中新增 \texttt{absolute\_}\allowbreak\texttt{mass\_}\allowbreak\texttt{error}，
改用公共偏移 $c=\max(\ell_{\text{full}})$。这一点在下文 E2b 中定量体现。

\subsubsection{E3：边级条件化 vs 共享压缩}

\textbf{目的}：为 H1 与 H2 提供机制级数值证据。

\textbf{方法}：在相同预算下比较 DCC-KV（逐边条件化）与 FastKV（共享压缩）相对 Dense 的
误差。H1 断言同一源块对不同目的端的紧凑 KV 显著不同，以 KL 散度 $> 0.5$ 为判据，
并以 JS 散度（有界）与选中索引的 Jaccard 重叠作为不依赖平滑系数的伴随证据。
H2 采用\textbf{配对 bootstrap + 单侧置换检验}：对同一个（目的端, 预算）组合，
两种方法面对同一份源块与同一组探针 Query，故误差差异是同源配对量。

\textbf{结果}：修正 $\beta$ 链路口径后重测（每个条件 $192$ 个配对样本，
覆盖关注强度 $\{0,2,4,8,16\}$ 与预算 $\{16,32,64,128\}$，共 $20$ 个条件）：

\begin{itemize}
  \item H1 成立：$20$ 个条件\emph{全部}满足判据。同一源块对不同目的端的紧凑 KV
        在 KL、JS 与选中索引重叠三项上均显著偏离种子噪声底线
        （KL 最低为噪声底线的 $1.60$ 倍），而选中索引的 Jaccard 重叠低至 $0.032$；
        KL 中位数落在 $5.6$--$15.4$，平滑上限约为 $19.4$，
        故 $0/20$ 个条件出现饱和。该判据的自变量是\emph{目的端}而非 $\beta$，
        因此未按 $\beta$ 分层。
  \item H2 方向\textbf{稳定}：在 $\beta$ 全量口径下，$20$ 个条件\emph{全部}
        支持 DCC-KV（$3218/3840$ 个配对样本更优），汇总配对差异 $-0.314$
        （$\mathrm{CI}_{95}=[-0.325,-0.303]$，$p<10^{-6}$），方向一致。
        另外两种口径（$\beta/M$、不加 $\beta$）各有 $18/20$ 个条件支持 DCC-KV、
        $2$ 个不显著（均出现在关注强度 $\le2$ 且 $B=32$ 处），
        汇总差异为 $-0.219$ 与 $-0.214$，同样\textbf{无一反转}。
        早期版本中"方向在高关注强度处翻转"的现象在口径修正后\emph{不再出现}，
        因此该翻转确系实现问题所致的伪影，而非 H2 本身的属性。
\end{itemize}

\textbf{边界（必须保留）}：以上是合成数据上的\emph{机制级}证据——被测量的是
注意力分布与线性输出的重构精度，不是任务指标。H2 的\emph{任务级}证据
（准确率、生成质量）仍需 GPU 侧的 E6，本节不据此声称 H2 已被证实。

\subsubsection{E2b：$\beta$ 链路口径的判定}

\textbf{动机}：\S\ref{sec:exp-cpu} 的早期运行发现 $\beta$ 的拟合与施加载荷不一致，
需要判定正确口径。候选共六种，逐一在留出 Query 上实测
（\texttt{experiments/}\allowbreak\texttt{cpu/}\allowbreak
\texttt{e2b\_beta\_}\allowbreak\texttt{convention.py}）。

\textbf{为何置于 E3 之后}：该口径问题并非设计时预见到，而是在 E3 的配对检验
出现"方向随关注强度翻转"这一异常时才暴露出来的——先看到异常，再回头定位到
口径，因此叙述顺序与发现顺序一致。E2b 的结论是 E3 重测（以及 E2 的度量更正）
的前提，故在这一步完成之前，E2/E3 的任何方向性判断都不应对外声明。

\textbf{判定的关键：度量必须选对}。$\beta$ 加在 logit 上，而
$\mathrm{softmax}$ 对 logit 的整体常数位移免疫。因此
\textbf{只要独立地看单个块，$\beta$ 的常数分量完全不可观测}——
单块度量只能看到 $\beta$ 的跨 Key 离散度。
而 $\beta$ 的职责恰恰是恢复块的未归一化质量，质量只在\emph{与其他块共处一个
softmax 分母}时才有意义：最终输出是各块贡献的加权混合，权重正比于各块的
未归一化质量。故本文引入\textbf{归并侧度量}
\texttt{mixture\_}\allowbreak\texttt{relative\_}\allowbreak\texttt{error}：把源块与一个固定上下文块拼接后再与 Dense 比较。
这正是源论文 Appendix A.2 "mass-preserving" 论证的落点。

\textbf{判定结论}：（i）$\beta$ 的系数\textbf{应为 $1$}，两侧一致。
依据是源论文 Eq.(2) 的 $\sum_j \exp(\ell_j+\beta_j)$ 与本文自身
Eq.(15)(16) 中 $w=\exp(\beta)$ 直接乘在 $\exp(\ell)$ 上，两处都是系数 $1$。
（ii）质量目标必须为\textbf{未归一化}的 $\sum_k \exp(\ell_k)$，而非
$\mathrm{softmax}$ 沿 Key 轴之和。（iii）$1/M$ 系笔误，已移除。

\textbf{定量依据}（$45$ 个配对样本，$\lambda_\beta=3\times10^{-2}$；
因本小节的自变量是\emph{口径}，故不启用箱约束以隔离该变量）：

三条要点：
（1）原状口径的绝对质量误差是正确口径的约 $10$ 倍，且在归并侧比关闭 $\beta$
显著更差（$38/45$ 配对落败，$p<10^{-4}$），即\textbf{原实现对结果有实质损害}；
（2）修正口径后，$\beta$ 在归并侧显著优于关闭 $\beta$（$37/45$，$p<10^{-4}$），
绝对质量误差 $0.577 \to 0.174$（per-key）与 $0.171$（标量），
\textbf{$\beta$ 机制真正生效}；
（3）$\beta$ 退化为\textbf{单一标量}时配对优势最一致（$44/1$），
归并误差 $0.448$ \emph{低于} per-key 的 $0.460$，绝对质量误差亦更低，
单块误差二者基本相同（$0.525$ 对 $0.524$）。这提示"恢复块质量"这一标量
自由度已承担主要收益，per-key 的额外自由度是净成本——
\S\ref{sec:exp-e10} 判定其根因，\S\ref{sec:exp-e11} 进一步给出
"per-key 自由度值多少、$\lambda_\beta$ 该取多少"的定量答案。

\textbf{一个仍未解释的现象}：非负最小二乘的解允许 $w_j \to 0$，
实测有相当比例的 $\beta$ 被压到 clamp 下界（相当于"软剔除"某些 Key）。
这与本文把 $\beta$ 描述为"质量重加权"而非"二次选键"的意图不符。
该现象在 \S\ref{sec:exp-e10} 中定位并处理。

\subsubsection{E10：$\beta$ 稀疏塌缩的判定与修复}
\label{sec:exp-e10}

\textbf{动机}：上节留下一处未解释的现象——非负最小二乘的解允许 $w_j\to0$，
实测相当比例的 $\beta$ 落在 clamp 下界（$w=10^{-6}$，即 $\beta=-13.8155$），
效果接近"软剔除部分 Key"。这与本文把 $\beta$ 描述为"质量重加权"而非
"二次选键"的定位不符。本节把它从现象变成可证伪的命题。

\textbf{候选根因与判定设计}：三个互斥假设。
（i）\emph{零空间}：$\mathrm{rank}(G)\le M$，$B>M$ 时有 $B-\mathrm{rank}(G)$
个方向不受数据约束，解落到下界；
（ii）\emph{极端值}：只有少数 Key 需要极负的 $\beta$，箱约束即可解决；
（iii）\emph{正则不足}：病态方向未被 $\lambda_\beta$ 压制。
设计为 $M\in\{8,16,32\}\times B\in\{8,16,32,64\}\times 5$ 种子 $\times 3$ 目的端
$=180$ 格，$\times 10$ 种规格 $=1800$ 次构造。箱约束阈值取源论文
Appendix C.2 中与本文选键分支配套的 $[-3,3]$，以及 OMP 支的 $[-7,7]$，均非自拟。

\textbf{假设（i）被否}：在 $\lambda_\beta=0$ 的规格上比较死键数与零空间维数，
二者平均绝对偏差达 $15.5$——零空间很大（如 $M=8,B=32$ 时 $24$ 维），
而实测死键数接近 $0$。\textbf{塌缩不是秩现象}。

\textbf{真正的代价在容量侧}：$\beta$ 的\emph{离散分量}压低有效预算、抬高
$V$ 回归残差。逐 $(\text{seed},\text{dest},M,B)$ 配对（$n=180$）的结果：

（1）箱约束 $[-3,3]$ 是\textbf{必要但远不充分}的。它把 clamp 率由 $0.054$
降到 $0$，并使 $B_{\text{eff}}/B$ 与 $V$ 残差一致改善（$169/180$ 与 $128/180$
配对更优，$p<10^{-4}$），但误差改善很小（输出 $\Delta=-0.0011$、
归并 $\Delta=-0.0007$、$|\text{mass}|$ $\Delta=-0.0009$）。
即源论文担心的"极值软剔除"确实存在，\emph{但不是主要损失来源}。

（2）真正的旋钮是\textbf{离散度本身}。$\lambda_\beta$ 由 $10^{-3}$ 增至 $10^{-2}$
即取得比箱约束更大的收益（输出 $\Delta=-0.0054$、归并 $\Delta=-0.0060$；
$B_{\text{eff}}/B$ $+0.047$、$V$ 残差 $-0.011$，均 $p<10^{-4}$）；
与箱约束叠加后在 $B>M$ 一侧收益最大（输出 $\Delta=-0.0118$、
归并 $\Delta=-0.0111$，$78/12$ 与 $76/14$，$p<10^{-4}$），
而在 $B\le M$ 一侧不显著（$p=0.55$、$0.32$）。

\textbf{一个结构性分解}。把 $\beta$ 退化为单一标量后，它与"全链路关闭 $\beta$"
在 $V$ 回归上\textbf{逐位相同}：两者的留出输出误差（$0.500$）、
$B_{\text{eff}}/B$（$0.832$）、$V$ 残差（$0.053$）三项完全一致。
原因是常数 $\beta$ 在 $\mathrm{softmax}$ 中被抵消，不改变回归设计矩阵。
二者唯一的差别在\emph{归并}误差（$0.414$ 对 $0.516$）。
据此可把 $\beta$ 的贡献干净地拆开：\textbf{块级常数分量修正块质量，
这是它唯一的收益来源；per-key 离散分量改变块内重加权，
这是它唯一的代价来源}（有效预算 $0.832\to0.671$、$V$ 残差 $0.053\to0.103$，
分别在 $170/180$ 与 $148/180$ 格上变差）。

需要注意两个极端都不是最优：$\lambda_\beta=10^{-1}$ 的留出输出误差（$0.495$）
低于标量（$0.500$）与关闭 $\beta$（$0.500$），说明\textbf{少量离散度仍有价值}。
因此结论不是"per-key 自由度无用"，而是"\emph{无约束}的 per-key 自由度不划算"。

\textbf{与源论文的一处口径差异}：源论文 Appendix C.2 称 $\ell_2$ 正则在
"一切正的 $\lambda$ 上都降低性能"。本文测得 $\lambda_\beta$ 增大\emph{一致改善}
误差。该分歧源于 $\lambda$ 的定义不同：本文的 $\lambda_{\text{eff}}=
\lambda\cdot\mathrm{mean}(\mathrm{diag}(G^\top G))$ 是尺度无关的相对量，
源论文用的是绝对 $\lambda$，两者不可直接比较。
故此处仅报告"在本文口径下"的结论，不据此否认源论文的观察。

\textbf{采纳与遗留}：本文把箱约束 $[-3,3]$ 设为实现中的默认
（\texttt{DEFAULT\_}\allowbreak\texttt{BETA\_}\allowbreak\texttt{BOUND}），
理由是它与源论文所选分支的配置一致、零成本地消除了软剔除，
并使 $\beta$ 的行为与其"质量重加权"的定义相符。
$\lambda_\beta$ 的提升同样是净收益，但取值不能凭"越大越好"外推——
\S\ref{sec:exp-e11} 在全部 $12$ 档 $\lambda_\beta$ 上细化扫描后，
把默认值定为 $3\times10^{-2}$
（\texttt{DEFAULT\_}\allowbreak\texttt{LAMBDA\_}\allowbreak\texttt{BETA}）。
该现象的直接后果是：$V$ 回归的有效预算比名义预算更低，
报告"预算–精度"曲线时须同时报告 $B$、$M$ 与 $B_{\text{eff}}/B$。

\subsubsection{E11：$\lambda_\beta$ 的细化扫描与默认值定位}
\label{sec:exp-e11}

\textbf{动机}：\S\ref{sec:exp-e10} 已确认 $\lambda_\beta$ 是比箱约束更有效的旋钮，
但当时只对照了 $10^{-3}$、$10^{-2}$、$10^{-1}$ 三档，且后两档在归并误差上互有胜负
（$0.427$ 对 $0.417$）。在把它写成默认值之前必须先回答两个问题：
最优点是否落在扫描区间\emph{内部}？以及 $\lambda_\beta\to\infty$ 时链路是否真的
退化为"关闭 $\beta$"？

\textbf{设计}：在与 E10 完全相同的 $180$ 格上（$M\in\{8,16,32\}$、$B\in\{8,16,32,64\}$、
$5$ 种子、$3$ 目的端），固定箱约束 $[-3,3]$，把 $\lambda_\beta$ 扩到 $12$ 档

有效预算比。

\textbf{（1）最优点落在扫描区间内部，不在端点。}归并误差沿 $\lambda_\beta$ 先降后升：
由 $10^{-3}$ 的 $0.435$ 降到 $10^{-1}$ 的 $0.417$（区间内最小），
再随 $\lambda_\beta$ 增大回升到 $10^3$ 的 $0.513$，向"关闭 $\beta$"的 $0.516$ 收敛；
输出误差在 $\lambda_\beta\ge3\times10^{-2}$ 后基本持平（$0.491$–$0.501$）。
两条曲线都不在扫描端点取最优，故"$\lambda_\beta$ 越大越好"不成立（图~\ref{fig:lambda-curve}）。

\textbf{（2）不存在全局最优，默认值只能按判据取。}逐 $(\text{seed},\text{dest},M,B)$
格取 $\arg\min$ 后，最优点随\emph{所在域}与\emph{所用指标}移动近三个数量级：
$B\le M$ 域的中位最优 $\lambda_\beta\approx0.1$，而 $B>M$ 域的中位最优在输出指标上达
$10^3$、在归并指标上约 $0.3$。逐格调参等于把这一自由度用于拟合评测集，
故只能按一个公开判据取全局默认。

\textbf{（3）大 $\lambda_\beta$ 极限与"关闭 $\beta$"一致（渐近前提成立）。}
只看最大的 $\lambda_\beta$ 会分不清"尚未进入渐近区"与"前提不成立"，故逐档检查：
$\beta$ 的标准差由 $1.08\times10^{-1}$（$\lambda_\beta=10$）单调降到
$3.4\times10^{-3}$（$\lambda_\beta=10^3$），而各指标相对"关闭 $\beta$"的偏差
$\max|\Delta|$ 始终不超过 $\beta$ 标准差的 $1.61$ 倍。比值有界意味着 $\beta\to0$ 时
$\Delta\to0$，即"大 $\lambda_\beta$ 退化为关闭 $\beta$"在数值上成立。

\textbf{（4）管线互校。}本脚本与 E10 在四个同规格（无箱 $10^{-3}$/$10^{-1}$、标量、
关闭 $\beta$）上的中位数逐位一致（$|\Delta|<10^{-16}$），
故两套结果可置于同一张表内比较。

\textbf{（5）默认值取 $3\times10^{-2}$ 的判据。}相对旧默认 $10^{-3}$，
该档的两个指标在配对 bootstrap 上均稳健改善（输出 $\Delta=-0.0119$，
$\text{CI}_{95}=[-0.0196,-0.0040]$，$p=0.0014$；归并 $\Delta=-0.0118$，
$\text{CI}_{95}=[-0.0181,-0.0055]$，$p=0.0003$），且在 $B\le M$ 一侧统计中性
（$p=0.67$、$0.52$，即不显著变差），箱绑定率由 $5.7\%$ 降到 $1.6\%$。
其最差单格退化（$M=8,B=8$）为 $7.3\%$，而 $10^{-1}$ 在同一格为 $20.3\%$。
故取满足"两指标稳健改善且域中立"的\emph{最小}档 $3\times10^{-2}$，
而非误差最低的 $10^{-1}$。实现默认值已同步为
\texttt{DEFAULT\_}\allowbreak\texttt{LAMBDA\_}\allowbreak\texttt{BETA}。

\textbf{两处必须如实记下的分寸}。其一，归并误差在 $\lambda_\beta$ 阶梯上的最小值
（$0.417$）仍略高于标量 $\beta$（$0.414$）：归并度量的是块质量，
而块级常数分量恰是它的唯一收益来源（\S\ref{sec:exp-e10}），
per-key 离散度在此是净成本；但输出误差上 per-key 在 $\lambda_\beta\ge10^{-1}$ 后
反超标量（$0.495$ 对 $0.500$），说明离散度虽压低块质量恢复、却改善了输出拟合。
其二，本文的 $\lambda_{\text{eff}}$ 是尺度无关的相对量（见 \S\ref{sec:exp-e10}
的口径说明），故本节全部结论只在该口径下成立。

\subsubsection{E9：信息瓶颈的旋钮定位}

\textbf{动机}：Value 回归的设计矩阵 $X_{s\to r}$ 行数等于代表 Query 数 $M$，
故 $\mathrm{rank}(X)\le M$。当 $B>M$ 时回归欠定。若信息瓶颈真是 $M$ 而非 $B$，
则本文以"扫描预算 $B$ 画帕累托前沿"为主线的叙述需要重估。

\textbf{设计}：$M\in\{4,8,16,32,48\}$ $\times$ $B\in\{8,16,32,64,128\}$，
$5$ 个种子 $\times$ $3$ 个目的端，共 $375$ 格；$\beta$ 取当前默认
（箱约束 $[-3,3]$、$\lambda_\beta=3\times10^{-2}$，见 \S\ref{sec:exp-e11}）。
三件事同时测量：
（i）\emph{fit}：正常链路；
（ii）\emph{oracle}：固定同一套选中 Key 与同一个 $\beta$，但用\emph{评估 Query
自己}拟合 $V$——它作弊，因此给出"预算 $B$ 下的可达上界"；
（iii）\emph{gap} $=$ fit $-$ oracle，即 $M$ 不足导致的估计误差。
所有指标都在**留出 Query** 上评估，留出集从未参与选键、$\beta$ 拟合或 $V$ 回归——
否则"增大 $M$"会因为见过更多评估点而自动获胜，结论将退化为同义反复。

\textbf{结论（较早期判断更为精确）}：两个旋钮\emph{都有效，但职责不同}。

\begin{itemize}
  \item \textbf{$B$ 决定可达上界}：oracle 曲线沿 $B$ 由 $8\to128$ 下降
        $80.3\%$（$M=4$）到 $85.1\%$（$M=48$），且 $M$ 越大降幅越大，
        说明表示能力的收益是实的、并且要靠 $M$ 才能兑现。
  \item \textbf{$M$ 决定能否触及上界}：gap 沿 $M$ 由 $4\to48$ 缩小
        $78.6\%$（$B=8$）到 $74.7\%$（$B=128$）。
  \item 在\emph{可实现}链路里，沿 $M$ 轴的平均相对改善为 $0.557$，
        沿 $B$ 轴为 $0.304$——\textbf{$M$ 的边际收益约为 $B$ 的 $1.8$ 倍}。
  \item 但\textbf{$B$ 不是次要旋钮}：它的收益是 $M$ 的函数。在 $M=4$ 时
        $B$ 由 $8\to128$ 只带来 $11.6\%$ 的改善，而在 $M=48$ 时带来 $55.8\%$。
        也就是说，"只扫 $B$ 而固定 $M$"会把 $B$ 的收益系统性低估。
  \item gap 随 $B$ 单调\emph{增大}（$M=4$ 时 $0.248\to0.565$），
        说明预算越大越需要更大的 $M$ 才能兑现。
\end{itemize}

因此本文的叙述不必推翻，但必须\textbf{把 $M$ 与 $B$ 一起扫描}，
并在报告任何"预算--精度"曲线时同时报告所使用的 $M$；
否则读者无法区分"预算不够"与"估计不足"。

\textbf{与 E10/E11 的关系}：本小节的全部数字是在\emph{当前默认}
（箱约束 $[-3,3]$、$\lambda_\beta=3\times10^{-2}$）下重跑的。
\S\ref{sec:exp-e10} 与 \S\ref{sec:exp-e11} 测得该配置相对"无箱约束、$10^{-3}$"
对误差的影响在 $0.01$ 量级以内，故它们关于有效预算的发现与本节结论不冲突：
$B_{\text{eff}}/B$ 在 $B>M$ 一侧约为 $0.70$、在 $B\le M$ 一侧约为 $0.81$，
即名义预算 $B$ 的可兑现部分只有七八成。

\subsubsection{E4：分布式等价性}

\textbf{目的}：验证同步版 DCC-KV 与完整分布式注意力在数值上一致，且变长消息在真实多进程
环境下正确传递。

\textbf{已有证据}：Ring Attention 与 Dense 的最大偏差 $< 10^{-5}$（$L=256$，四块，
$\mathrm{FP64}$）。

\textbf{已补}：通过三档对照（完全不压缩、预算等于块长、真实压缩）分离误差来源。
完全不压缩且不加偏置时，同步 DCC-KV 与 Dense 的最大绝对偏差为
$2.5\times 10^{-7}$（$\mathrm{FP32}$），证明通信与归并路径本身是数值干净的；
压缩设定下的偏差全部来自构造近似。

\textbf{关于多进程路径的一处更正}：本文早期版本记录 \texttt{all\_reduce}、
\texttt{broadcast} 与变长 \texttt{all\_to\_all\_v} 的测试在本机 Windows 环境下以
\texttt{OSError: [WinError 6] 句柄无效} 失败。经复核，\emph{该归因有误}：
实际异常是 \texttt{AttributeError: Can't get local object
'launch\_dist.<locals>.wrapped\_fn'}，即 \texttt{mp.spawn} 在 spawn 启动方式下
必须序列化目标函数，而旧实现把包装函数定义成了 \texttt{launch\_dist} 的
\emph{局部}函数（仅在 fork 平台可用）。把包装函数提到模块级后，这三条路径在本机
Windows 上\textbf{全部通过}，因此 E4 现在同时具备单进程 mock 与真实多进程
\texttt{gloo} 两条通过记录；同期其余数值结论未发生变化。

\subsubsection{由实验反查并修复的实现问题}

执行上述脚本的过程先后定位了八处实现问题。与早期版本不同，本次\emph{已按
最合理口径修复}前七处，并在仓库测试套件上验证；第八处（$\beta$ 稀疏塌缩）
最初如实保留为待办，随后由 E10 定位并采纳修复（见 \S\ref{sec:exp-e10}）。

\emph{其一，块质量恒为 1（已修）。}\texttt{compact\_kv.py} 中以
$\mathrm{softmax}$ 沿最后一维求和构造 \texttt{block\_mass}。沿 softmax 的归一化
维度求和恒等于 $1$，该量不携带任何信息，$\beta$ 的拟合目标退化。
已改为未归一化的 $\sum_k \exp(\ell_k)$（含防溢出的全局偏移），
与源论文 Eq.(2) 及 \texttt{calibration.py} 的文档一致。

{\sloppy
\emph{其二，$\beta$ 的训练与推理口径不一致（已修）。}
\texttt{value\_}\allowbreak\texttt{regression.py} 在构造设计矩阵时对 $\beta$ 施加 $1/M$ 缩放，
而推理路径使用未缩放的全量 $\beta$。已统一为系数 $1$，并同步修正
\texttt{calibration.py} 与 \texttt{compact\_kv.py} 的文档。
这是 E3 中 H2 方向由"局部翻转"变为"全线稳定"的直接原因。
\par}

\emph{其三，非负岭回归求解器不收敛（已修）。}
\texttt{nonneg\_}\allowbreak\texttt{least\_}\allowbreak\texttt{squares} 使用固定步长 $10^{-2}$ 的投影梯度。
当目标量级为未归一化质量（可达 $L_s$）时，梯度的 Lipschitz 常数增大，
固定步长越过稳定域，$w$ 反复被投影 clamp 到 $0$，$\beta$ 全部顶到
$\log(10^{-6})=-13.8155$ 的下界。已改为步长 $1/L$（$L$ 为
$A=G^{\top}G+\lambda I$ 的最大特征值）并采用尺度无关的正则
$\lambda_{\text{eff}}=\lambda\cdot\mathrm{mean}(\mathrm{diag}(G^{\top}G))$。

\emph{其四，Value 回归在 $B>M$ 时欠定（已测量，未修）。}
$\mathrm{rank}(X)\le M$，$B>M$ 时解完全由正则项决定。
E9 已把这一关系的后果量化（见 \S\ref{sec:exp-cpu} 的 E9），
它不再是一个未经验证的推测，而是一个有网格数据支撑的设计约束。

\emph{其五，精度限制阻塞 $\mathrm{FP64}$（已修）。}
\texttt{representative\_}\allowbreak\texttt{query.py} 的 \texttt{rademacher\_projection} 写死
\texttt{.float()}，使 float64 输入报 dtype 不匹配，整条构造链无法在
$\mathrm{FP64}$ 下运行。这直接阻塞了 $\mathrm{FP64}$ 的误差分析与三个测试。
已改为按输入张量的 dtype 生成。

{\sloppy
\emph{其六，CUDA 设备不匹配（已修）。}
同上文件中的 \texttt{torch.}\allowbreak\texttt{Generator()} 与
\texttt{torch.}\allowbreak\texttt{randint} 默认建在 CPU，
\texttt{value\_}\allowbreak\texttt{regression.py} 的 \texttt{torch.}\allowbreak\texttt{eye} 未指定 device。
前两者使构造链在 CUDA 张量上直接报错，后者会在 GPU 上创建 CPU 张量。
均已改为跟随输入的 device。这是 GPU 侧 A1/A2/A3 的硬前置。
\par}

\emph{其七，包导出缺失与双导入根不兼容（已修）。}
\texttt{dcc\_}\allowbreak\texttt{kv\_}\allowbreak\texttt{ref/}\allowbreak
\texttt{\_\_init\_\_.py} 未导出
\texttt{merge\_}\allowbreak\texttt{softmax\_}\allowbreak\texttt{states\_}\allowbreak\texttt{list}
与 \texttt{attention\_output\_from\_state}；\texttt{baselines/} 与
\texttt{distributed/} 中的五个模块使用 \texttt{from ..dcc\_kv\_ref import}，
在"把 \texttt{src/} 直接加入 \texttt{sys.path}"的调用方式下报
\emph{attempted relative import beyond top-level package}。

\textbf{这一条有一个必须记录的后果}：在修复前，
\texttt{tests/}\allowbreak\texttt{test\_}\allowbreak\texttt{dist\_}\allowbreak\texttt{equivalence.py}
因缺少导出而\textbf{整个模块无法收集}，进而导致 pytest 在收集阶段中止、
\textbf{测试套件中的零个测试被执行}。也就是说，早期版本中作为 E2/E3 证据引用的
\texttt{test\_}\allowbreak\texttt{dcc\_}\allowbreak\texttt{kv\_}\allowbreak\texttt{lower\_}\allowbreak\texttt{error\_}\allowbreak\texttt{than\_}\allowbreak\texttt{shared} 与
\texttt{test\_}\allowbreak\texttt{fast\_}\allowbreak\texttt{kv\_}\allowbreak\texttt{vs\_}\allowbreak\texttt{dense\_}\allowbreak\texttt{within\_}\allowbreak\texttt{tolerance} \textbf{从未真正运行过}。
修复后的实测状态为：该文件 $3$ 失败 / $10$ 通过（修复前为 $6$ 失败 / $7$ 通过，
三个 $\mathrm{FP64}$ 相关测试因 dtype 缺陷报错）；全仓库
$44$ 通过 / $11$ 失败，当时把其中 $8$ 项归为"本机 Windows 多进程 spawn 的
环境限制"。该归因已被复核推翻：这 $11$ 项在下一轮逐项定位后\emph{全部}修掉，
主因是 \texttt{mp.spawn} 在 spawn 启动方式下无法序列化局部（或测试内定义的）
函数，见上文 E4 小节的更正段；其余是测试自身构造不当（异形 $d_v$ 的归并、
mock 模式下断言真实 backend 语义、单进程 \texttt{args} 期望、临时脚本路径未转义）
以及上文 E2 小节所述的两条压缩基线断言。修复后全仓库为
$57$ 通过 / $0$ 失败 / $2$ 个 \texttt{xfail}，该文件为 $15$ 通过 /
$2$ 个 \texttt{xfail}；两条压缩基线断言与本文的 $\beta$ 改动无关。

\emph{其八，$\beta$ 的稀疏塌缩（已定位并采纳修复）。}
非负最小二乘允许 $w_j\to0$，实测相当比例的 $\beta$ 落到 clamp 下界，
效果接近"软剔除部分 Key"。\S\ref{sec:exp-e10} 判定其根因\emph{不在秩}
（死键数与零空间维数的平均绝对偏差达 $15.5$），而在 $\beta$ 离散分量的
容量代价；已按源论文 Appendix C.2 中与本文选键分支配套的箱约束 $[-3,3]$
设为实现默认（\texttt{DEFAULT\_}\allowbreak\texttt{BETA\_}\allowbreak\texttt{BOUND}），
clamp 率由 $0.054$ 降为 $0$。$\lambda_\beta$ 的取值由 \S\ref{sec:exp-e11}
在 $12$ 档上的细化扫描定位，已定为默认值 $3\times10^{-2}$。

\textbf{小结}：八处问题中七处已修复——其五、其六使 GPU 侧实验的前提条件成立，
其四解除 $\mathrm{FP64}$ 阻塞，其一、其二、其三使 $\beta$ 机制从"退化/有害"
变为"在归并侧显著有效"，其七使测试套件从"零个测试被执行"变为可运行；
其八经 E10 从"未解释的现象"定位为"离散度的容量代价"，并采纳源论文的箱约束
作为默认，$\lambda_\beta$ 的默认值则由 E11 的细化扫描定为 $3\times10^{-2}$。

\subsection{待执行的 GPU 实验}
\label{sec:exp-gpu}

以下实验依赖 GPU 与多卡环境，尚未执行。协议如下，结果补齐后填入对应表格。

\subsubsection{E5：消融实验}

消融设计覆盖组件与预算两个维度。

\paragraph{A1 通信集大小。}扫描有效边数 $|\mathcal{E}_s|$，观察构造开销与通信开销随设备数
的分配比例，用于检验式~\eqref{eq:cost-build} 中 $|\mathcal{E}_s|$ 倍构造代价的实际影响。

\paragraph{A2 压缩预算。}在 5 档预算下测量任务指标与通信量，绘制精度--通信量曲线。
该曲线是本文计划中最主要的可视化结果：它同时呈现压缩收益与精度代价，并与
FastKV、APB 的同类曲线叠加比较。

\textbf{标注口径}：只有当精度与通信量两轴取自\textbf{同一方法}时，该曲线才是严格意义上的
帕累托前沿。当前实现中两轴不同源（通信量取自 DCC-KV 的逐边预算，精度取自共享的
top-$B$ 裁剪），程序据此记录 \texttt{pareto\_frontier\_valid=False}。故本稿一律称其为
\textbf{预算--精度参考曲线}，不称帕累托前沿；同源前沿须待 CompactKV 到 GPU attention
kernel 的通路打通后方可绘制。

\paragraph{A3 组件拆分。}四个变体：完整 DCC-KV、（i）移除质量偏置 $\beta$、
（ii）移除 Value 回归（直接取所选 Key 对应的原始 Value）、（iii）二者同时移除
（退化为纯 Key 选择）。按 H3，移除 $\beta$ 应导致 $\ge 0.5$ 点退化，移除 Value 回归应导致
$\ge 1.0$ 点退化。

\paragraph{A5 异步 vs 同步。}固定其他条件，比较异步流水与同步实现的 p50 延迟。按 H4，
异步应带来 $\ge 1.05\times$ 的 p50 加速。此外应同时报告
$T_{\text{comm}} / T_{\text{comp}}$ 的实测值，以便按式~\eqref{eq:speedup-bound} 判断
实测加速比与理论差距的归因。

\subsubsection{E6：主表与可扩展性}

主表为 $3$ 模型 $\times$ $4$ 上下文长度 $\times$ $2$ GPU 数 $\times$ $2$ 同步模式
$\times$ $3$ 基线 $= 144$ 个数据点，每点 $\ge 10$ 次 run。报告指标包括任务精度、
prefill 延迟（p50 与 p95）、端到端吞吐与跨设备通信量。

可扩展性按 H5 检验：设备数翻倍时加速应 $\ge 1.5\times$。若未达标，需按
\S\ref{sec:exp-negative} 的规范转为负结果讨论。

\subsubsection{E7：负结果与适用边界}
\label{sec:exp-negative}

按仓库发布清单的要求，以下四种条件必须显式报告结果，无论其是否符合预期：

\emph{短上下文（$L < 4$K）。}此时 $B/L$ 不再小，压缩的固定开销（代表 Query 交换与逐边
构造）占比上升，预期 DCC-KV 无收益甚至劣于精确注意力。这一边界需明确给出，而非回避。

\emph{低预算（$B < 1\%$）。}此时 $\epsilon_{\text{mass}}$ 与 $\epsilon_{\text{out}}$ 均
显著增大，用于确定方法的可用压缩下界。

\emph{强检索任务。}检索任务对精确的 token 级定位敏感，压缩可能系统性地丢失关键条目。
这是对"误差不随块数发散"这一性质的压力测试。

\emph{batch = 1。}此时计算侧难以饱和，$T_{\text{comp}}$ 偏小，
式~\eqref{eq:speedup-bound} 预测异步收益受限。该场景直接检验流水的收益边界。

\subsubsection{E8：数值稳定性}

把 \S\ref{sec:exp-cpu} 的 E0 扩展到 $\mathrm{FP16}$/$\mathrm{BF16}$、$K \ge 32$ 个块与
更深的归并树结构，测量顺序无关性在低精度下的失效边界。该实验的结果决定异步实现能否在
真实推理精度下安全使用，是工程可行性的关键一环。

\subsubsection{执行框架与前置缺口}

E5--E8 的执行框架已实现于 \texttt{experiments/gpu/}。框架的一条硬性约束是：
环境不达标时\textbf{不产出任何结果文件}，而是以退出码 $3$ 中止，
以免在 CPU 上跑出一批无意义的数字污染结果表。三个公共模块分别负责环境闸门与
元数据（\texttt{\_env.py}）、变长 All-to-Allv 与同步/异步流水（\texttt{\_comm.py}）、
模型加载与 KV 预算约束（\texttt{\_hf.py}）。

框架同时把\textbf{计时拆成四项}——逐边构造 $T_{\text{build}}$、通信
$T_{\text{comm}}$、本地计算 $T_{\text{comp}}$ 与总耗时 $T_{\text{total}}$。
这一拆分是必要的：异步的收益只来自 $T_{\text{comm}}$ 与 $T_{\text{comp}}$ 的重叠，
若把构造代价隐含地并入其中任何一项，式~\eqref{eq:speedup-bound} 的归因就会失真。

框架在执行前会逐项检查前置条件，并把未满足的项以 \texttt{blocked} 状态显式记账，
而非静默省略。当前存在四类缺口：
（i）缺少把紧凑 KV 送入 GPU 注意力核的通路，阻断 A3 与主表中的 DCC-KV 行；
（ii）紧凑 KV 构造链路目前仅在 CPU 张量上可用，阻断 A1/A2 的纯 GPU 构造口径；
（iii）三个基线（Ring Attention、APB、FastKV）在仓库中仅有 CPU 实现，
主表中对应行不可测；
（iv）异步 All-to-All 流水尚无接入真实模型前向的入口。
上述缺口的补齐清单已在代码中逐条列出，避免出现"看起来完整但数值无出处"的主表。

由此引出一个必须写明的报告边界：主表中 \texttt{gpu\_count} 维度对不涉及跨设备
通信的方法没有意义，那四个需要多卡的方法又当前均被阻断，
因此 E6 \textbf{当前不能用于支撑 H5}。H5 须待 DCC-KV 的多卡实现就绪后单独测量。

本节的实验设计有三个特点值得指出。

第一，它把"可验证"与"待验证"严格分离：E0--E4、E2b、E9、E10、E11 给出的是接口正确性、数值等价性、
顺序无关性以及机制层面的证据，这些证据不依赖 GPU，因而是当前状态下唯一可对外声明的结论；
E5--E8 给出的是完整协议，其结果决定了本文关于精度与性能的主张能否成立。

第二，它把 H2 的证据等级明确限定在\textbf{机制级}。E3 在 $\beta$ 口径统一后重跑，
配对检验的方向成为稳定的：在 20 组（强度 $\times$ 预算）条件中 17 组显著、3 组不显著、
\textbf{无一反向}。这支持"边级条件化在混合输出层面优于共享压缩"这一\textbf{机制性}判断，
但它是在合成数据上、以混合输出的相对误差为指标得到的，\textbf{不构成任务级证据}。
H2 的任务级结论须待 E6 在真实模型与真实长文本上测量后才能声明。
若把机制级证据读作任务级结论，就是把尚未测得的结论当作已有证据。

第三，E2b、E10、E11 与 E9 是把"实现缺陷"与"科学结论"分开处理的四例。E2b 的作用是先判定
$\beta$ 链路口径（E2/E3 的结论是否可信，取决于这一步）；E10 的作用是把一个观察到的
实现异常判定为\emph{机制的结构性代价}而非单纯的数值瑕疵；E11 的作用是在默认值写进
实现之前先确认该取值有内部最优与统计判据支撑，而非端点外推；E9 的作用是在结论写进正文
之前先确认旋钮的真实角色。四者均不产出可写入论文的\textbf{结果}，只产出\textbf{前提}。
这一区分同样适用于剩余章节：拿不准的前提，不得作为结论写入。

因此，本节当前能支撑的结论限于：紧凑 KV 构造流程在实现层面自洽且可复现；在线 Softmax
归并算子在 $\mathrm{FP64}$ 下满足顺序无关性；变长 All-to-All 消息在多进程环境下正确传递；
同步版分布式注意力与 Dense 的偏差处于压缩误差量级；在合成数据与统一口径下，边级条件化
在混合输出层面优于共享压缩（机制级）；$\beta$ 的收益与代价可干净分离——块级常数分量
修正块质量、是唯一收益来源，per-key 离散分量压低有效预算（$B_{\text{eff}}/B\approx
0.70$--$0.81$）、是唯一代价来源；$\beta$ 的两个校准参数（箱约束 $[-3,3]$ 与
$\lambda_\beta=3\times10^{-2}$）已由网格定位固定为默认，不再随任务调整。
关于任务质量、通信收益、多卡可扩展性以及与基线的
优劣对比，均待 GPU 实验完成后报告。
