## 二、今日完成项（6 项）

### 1. E13：误差界式(37) 首次被数值检验（新增实验）

论文 §5 给出了输出误差的上界，但此前**从未测过它紧不紧**——这是理论部分最容易被审稿人追问的一处。

- **界成立**：5760 个 Query 上**零反例**（相对容差 `1e-9`）。B = L_s 时取等号（此时确实无压缩）。
- **但界偏松**：RHS/LHS 中位数 **2.10**、95 分位 **3.51**、最小 1.00。
- **前置条件才是关键发现**：式(37) 要求 `Σ|δM_s| < S/2`。实测在**不加 β** 时该条件最高有 **100%** 的 Query 不满足，加 β 后降至 16.7%，且沿预算单调改善（B=8 时 91.0% → B≥128 时为 0%）。
- ⇒ **β 的第三个作用被确认**：不只是修质量、稳数值，还**扩展了这个界的适用范围**。

> 附带更正了论文性质 3 的一处归因：原文把"阻止误差发散"归因于符号抵消，实测不加 β 时 `|ΣδM|/Σ|δM|` **恒为 1.000**（完全同向叠加）。真正起作用的是**分母 S(q) 随块数增长**，符号抵消只是附加裕度。原文把它写成条件因而过强，已改。

### 2. E12：代表 Query 投影维度 `d_p` 的扫描（新增实验）

方法里 `d_p` 的取值此前**全是解析推导、没有实验依据**。

- JL 畸变随 `d_p` 单调下降（0.278 → 0.068），但**下游误差几乎持平**（ε_mass / ε_out 的差异落在种子极差内）。
- 选中集合的 Jaccard 相似度在 `d_p=4` 时相对 `d_p=64` 仅 0.524 ⇒ `d_p` 影响的是"**选了哪些**"，不是"**选得准不准**"。
- ⇒ **`d_p ≥ 8` 即饱和**，建议取值区间 `[8, 32]`。

### 3. E3 改为留出（heldout）协议重跑

原实现里**构造用的 Query 和评估用的 Query 是同一批**，属于样本内评估。

- 改为留出后，DCC-KV 相对共享压缩的优势从 **20/20 降到 18/20**（汇总 −0.167）。
- **优势大小随目的端可分性变化**：强度 0（负对照）**没有优势**（中位 +0.006）；强度 ≥8 时 12/12 显著。
- ⇒ 主张必须限定为「**当目的端确有可分关注区域时**」，不能写成无条件成立。

### 4. E0 补上「置换次数」轴

原脚本固定 200 次置换、只报一个最大值，**没有曲线**。

- 累计最大相对误差在 `n ≤ 25` 内即达 `n = 1000` 的 **88%** 以上；`200 → 1000`（5 倍）最大增长仅 **4.54%**。
- ⇒ 报出的是**稳定上界**，不是在上升的下界。
- 归并树形状（顺序 / 平衡 / 随机）**没有系统性方向**（12 格中 7 格不劣、5 格更差）⇒ 本规模下误差由浮点精度支配，归并结构不是可辨识的误差来源。**因此实现侧不采纳"用平衡归并"这条**——原来的设计预期被它自己的数据推翻了。

### 5. 误差度量口径表进论文（§6.2）

论文里并存 **6 个误差术语、4 套实现**，而正文此前**没有任何口径声明**，读者无法判断任意一个 ε 数字是单块量还是跨块量。

现在 §6.2 新增 `tab:metrics` 显式声明：§5 的 ε_mass(式35)/ε_out(式36) 是**跨块绝对量**，而旧的实验数字是**单块版本**——**二者不可互比、不可互相代入**。同时废弃了一个已被推翻的旧度量。

### 6. H2 判据接线 + 跨长度聚合规则

- H2 的「质量相近」参照物**改为精确注意力**（原先取共享压缩基线与"提升 ≥1.5pp"自相矛盾），判据为**单侧非劣检验** `CI_low(Q_DCC − Q_dense) > −δ`。
- 4 个上下文长度**分别判定、全部通过才算前提成立**（不是把数据池化在一起）。
- 机器可读实现在 `experiments/common/hypotheses.py`，H2 的缺口由「定义缺失」降级为「**参数待测**」。

## 四、遇到的问题与风险

### 风险 1（最重要）：现在租卡跑，产出的表填不进论文

本机可复现的一条命令即可验证：

```bash
python experiments/gpu/e6_main_table.py --plan
```

输出显示 E6 主表 6 个方法里 **4 个被阻断**：`fastkv_official`、`dcc_kv`、`ring`、`apb`。唯一可测的两个是 `dense`（精确注意力，精度上界参照）和 `kv_budget_shared`（脚本自己声明「这不是 FastKV」）。

**阻断原因全部是实现缺口，与租什么卡无关。** 详见 `docs/gpu_execution_plan.md`。

### 风险 2：H2 / H3 / H5 三个假设目前"判据未接"

这不是"结论未定"，而是**判据尚未接通**：

- H2 依赖 GPU 上才能取得的噪声底线与退化量 `delta_bad`；
- H3 待 A3 的 GPU 通路；
- H5 待"设备数翻倍"基准点的定义（且 E6 中需要多卡的四个方法全被阻断）。

### 风险 3：H2 的机制级方向稳定，但**不能替代任务级结论**

留出后仍 18/20 支持，方向三口径无一反向；但**那是合成数据上的机制级度量**，任务级（准确率 / 生成质量）结论**必须等 E6**。按既定纪律，拿不准的结论不写入论文。

### 风险 4：4 个表格有 label 但正文从未引用（打磨项）

`tab:metrics`、`tab:beta-convention`、`tab:beta-collapse`、`tab:knob` 存在但正文无任何 `\ref` 指向，读者无法被引导过去。
