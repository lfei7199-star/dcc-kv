## 0. 结论摘要

1. **机制层面，断言成立。** 逐式核对下来，DCC-KV 对 AM 的移植是**忠实**的：β 以系数 1 加在
   logit 上、质量目标取未归一化 `Σexp`、RMS 选键、V 回归用紧凑侧 softmax 权重、
   归并算子 ⊕ 满足交换律与结合律。并且 DCC-KV 的参考集是**目的端真实 Query 的子采样**，
   比 AM 用的「模型自生成的代理分布」**更贴近**将要参与注意力的那批 Query。
   故「把 AM 作用于目的端通信」这一步本身不引入新的近似。

2. **但「不会遇到性能不符」有一个前提被写丢了。** AM 的保证（Appendix A.2）
   是**对参考 Query 集合**的 in-sample 陈述：匹配质量与输出 ⇒ 任意后续 token 下全局注意力守恒。
   AM 满足该前提的方式是 **n ≈ 5×10⁴ 个参考 Query 对 t 个紧凑 Key**（n/t ≈ 10³–10⁴，严重超定）。
   DCC-KV 的参考集是**经通信传输的 M 个代表 Query**，M 与预算 B 同量级；**当 M < B 时
   β 拟合（M 个方程 / B 个未知数）与 V 回归（rank(X) ≤ M < B）双双欠定**，
   样本内残差可被压到 0，而样本外误差不受任何约束。⇒ 断言的正确形式是
   「在 **M 充分大于 B 且代表 Query 覆盖 Q_r 的支撑** 时，不应有性能不符」，
   而这两个前提在 AK27 §3–§4 与 §5 里**都没有位置**。

3. **「实验 vs 建模」不一致的地方只有一处，但是实质性的。** 实验层（E9/E10/E11）是**按
   (M, B) 两轴**组织的，并且明确以 `B ≤ M` / `B > M` 分域（`value_regression.py` 的 docstring
   直写「当 B > M 时 XᵀX 奇异」）；**建模只写了一轴 B**，M 在 §4.2 只被当作通信开销参数。
   §5 的误差界里没有 M 项，§7 自承「没有给出 M 与误差之间显式的关系」——
   理论自己承认缺的那一项，恰好是实验唯一在认真分域的那一项。

4. **此外查出 6 处具体的代码↔论文↔源论文不一致**（F1–F8，见 §3），
   其中 F1（岭正则的 λ=0 锚点从未跑过）与 F2（证据运行区间不在声明区间）
   直接影响「能否主张与 AM 同量级的质量」。

## 2. 关于「底层逻辑上不会遇到性能不符」的可否证性

### 2.1 成立的部分

- AM 的混合恒等式是「**对任意 Kfixed 都成立**」的充分条件式保证（App. A.2 式(5)）。
  DCC-KV 把它搬到「每条有向边」上，形态未变。
- 目的端 θ 的参考集是**真实 Query 的子采样**（AK27 式(12) 取回原始高维表示而非投影向量），
  而 AM 用的是**模型自生成的代理分布**。就「被匹配的 Query 是否就是将来要出席的那批」而言，
  DCC-KV 的条件化**严格更强**。
- 因此**「要不要条件化」本身不引入新误差**——这一点 AK27 §4.3 的表述是对的。

### 2.2 成立所依赖、但被写丢的两个前提

| 前提 | AM 如何满足 | DCC-KV 现状 | 是否免费 |
|---|---|---|---|
| **P1** 参考集相对预算**超定**（n ≫ t / M ≫ B） | n ≈ 5×10⁴ 对 t 个紧凑 Key | M 与 B 同量级；E10/E11 里 **50%** 的格 B > M，E9 里 **64%** | **不免费**：M 是经通信传的（`(N−1)M d_h`） |
| **P2** 参考集覆盖 Q_r 的支撑 | 5×10⁴ 个参考 Query | M 个 FPS 代表点，且 E9–E11 里 M/L_r ≈ 8%–33% | 不免费：同样是 M 的通信开销 |

**P1 的代价可以量化**（按 AK27 §5.1 的通信式）：令代表 Query 通信量与紧凑 KV 通信量相等：

```
(N−1)·M·d_h  =  |E_s|·B·(d_h+d_v+1)
双向注意力 |E_s| = N−1  ⇒  M/B = (d_h+d_v+1)/d_h
d_h = d_v = 128（fig4 的口径）  ⇒  M/B = 2.01
```

即 **M = 2B 时摘要开销才等于它压缩出来的 KV**。要 M = 20B 就要付 10 倍于紧凑 KV 的摘要，
但紧凑 KV 本身只有 dense 的 B/L_s，故总账仍是 `≈10B/L_s ≪ 1`。
**⇒ P1 在长上下文区间是付得起的，不是结构性障碍。**

### 2.3 那么缺的是什么

不是理论可能性，而是三件事：

1. **源论文在本分支的实际配置从未被跑过**（F1）。AM p.20 对 Highest-Attention-Keys 分支
   给的是「有界最小二乘 + e⁻³≤w≤e³」，**不含岭项**；它同时明确记录了
   「ℓ₂ 正则在估计 β 与 C_v 时**在所有正 λ 上降低性能**」。本仓库的
   `DEFAULT_LAMBDA_BETA=3e-2`、`lambda_value=1e-3` 都**不是 0**，
   而 **E11 的 λ 扫描下界是 1e-3，E2b 的 8 个预设全部跑在 λ=3e-2 上**
   ⇒ **λ=0 这根锚点在整个仓库里不存在**。于是：
   - 若 λ=0 更好 ⇒ 我们的默认值在两个指标上一起损失，且这正是「与 AM 同量级质量」的那一条；
   - 若 λ=0 更差 ⇒ 说明**我们所在的是欠定区间**，岭项在替秩缺失兜底，
     那它就必须在 §4.3.2 里连同「何时欠定」一起写明，而不是含混地写成「拟合信息不足时」。
   两种情况都会改动正文，所以**必须测**。

2. **全部 CPU 证据的运行区间不是论文声明的区间**（F2，详见 §4）。两个轴同时偏离且方向相反：
   `M/L_r` 偏大 ⇒ 代表 Query 覆盖**偏乐观**；`B > M` 占一半 ⇒ 回归**偏悲观**。
   因此现有数字**既不能当作保守下界，也不能当作乐观上界**。

3. **§5 的界里没有 M 项**（F3）。这意味着即使 P1/P2 成立与否决定了质量，理论框架
   **也没有位置去表达它**，只能靠 §7 自承「没有给出 M 与误差之间显式的关系」。

> 并**替换**旧落盘 —— `L_s=2048`、`M ∈ {4,8,16,32,48,96,192}`、`B ∈ {8,16,32,64,100}`、
> 525 格、`B/L_s = 0.0039–0.0488`、含 `B>M` 的行 **0%**。
> 表中 E9 行的 `375 / 256 / 0.031–0.50 / 64.0%` 是审计当时（`39063e7` 之前）的取值，
> **保留原文以便对照**；E10 / E11 / E2b 三行未变。

对照论文声明（`05-analysis.tex:106-107`、AK27 §4.2）：**`B ≪ L_s`、`M ≪ L_r`**。

两点观察：

- **`B ≪ L_s` 不成立到「半个块」的量级。** `B = 128、L_s = 256`（E9）意味着保留 50% 的 Key；
  AK27 §4.1 的 `B_{s,r} ≪ L_s` 与 AM 的头条 50×（2%）相差 25 倍。
- **`M ≪ L_r` 也不成立。** E11 每目的端 96 个 Query、`eval_fraction=0.5` ⇒ 拟合池 48，
  M ∈ {8,16,32} ⇒ **M/拟合池 = 17%–67%**；部署区间（`L_r≈10⁵、M≈64`）是 0.06%。
  ⇒ 合成实验里代表 Query 覆盖**远好于**部署情形。
- **欠定是实打实发生过的**：`x_eff_budget_frac` 最低 0.532（M=8, B=64），
  即 **47% 的预算在数值上不可辨识**；且它随 B 增大单调下降（M=8：0.856@B=8 → 0.532@B=64）。
  这正是 `value_regression.py:45-47` docstring 说的「B > M 时 XᵀX 奇异，增大预算 B
  不会带来更多可辨识的信息」。

**⇒ 结论**：CPU 侧的机制级证据**全部**取自一个「压缩很轻（B/L_s 高）、覆盖很好（M/L_r 大）、
但一半格子欠定」的区间，与论文声明的「压缩很重、M 极稀」**不同域**。两个偏离方向相反，
因此不能把现有数字单向地当成保守值或乐观值。

### 8.1 F7 的处置细节（本轮）

**缺陷**：`conditioning()` 把 `probe` 传成 `split.fit_queries[dest]`（整个拟合池，默认 `1024` 行），
于是 `X = softmax(probe·Kᵀ)` 的形状是 `[拟合池, B]`，`rank(X) ≤ min(拟合池, B)`
—— **与 `M` 无关**。而同格落盘的 `rank_upper_bound = min(M, B)` ⇒ 两者**不同源**，
表格里 `rank/min(M,B)` 的 `*` 标记失效。

**量化**（对 `_audit_tmp/e9_pre_rankfix/`，即论文 `tab:knob` 的数字来源，525 格）：

| 探针 | `rank > min(M,B)`（上界失效） | `rank == min(M,B)` |
|---|---|---|
| 旧：整个拟合池 | **255 / 525 格** | 269 / 525 |
| 新：`M` 个代表 Query | **0 / 525 格**（quick 规模 36/36 实测） | 全数 |

样例：`M=4, B=8` 旧报 `numeric_rank=8 > 上界 4`；新报 `4/4`。

**修法**：新增 `representative_queries_for()`，以**完全相同的参数**（同 `num_samples` /
同 `projection_dim` / 同 `seed`）重选那 `M` 个代表 Query —— `CompactKV` 不保存它们，
但 `select_representative_queries` 在固定 seed 下确定性 ⇒ 重选结果与 `build_compact_kv`
内部 Step 1 所用逐位一致。`conditioning(compact, rep_queries)` 因此拿到真正的
`M×B` 设计矩阵。

**影响面**：E9 的轴增益结论（`M` 轴 `0.421` vs `B` 轴 `0.146`）**不依赖**该诊断列，
故论文数字不受影响；只有 `cond_xtx` / `numeric_rank` 两列刷新。
