## 0. 复核前必读：三条铁律

这份项目的历史上，**被推翻的结论全部是踩了下面三条中的一条**。所以先记这三条，再动手。

### 铁律一：名字不是证据

一个臂（arm）叫 `budget_0.5`、`compressed`、`topk_0.25`，**不表示它真的压缩了**。  
本仓库真实发生过：所有标着 `budget_*` 的臂实际**一个 token 都没裁**，因为  
`compaction_mode="identity"` 的语义是「裁剪策略 = 恒等」，**不是**「不启用压缩」。  
那些 `acc=1.0000` 因此全是假的。

⇒ **判据**：任何"压缩臂"的准确率，先看它的 `compression_attestation.actually_cut` 是不是 `true`，**再看准确率**。

### 铁律二：全 1.0 不等于"无损"

`dense` 臂满分 ⇒ 没有上行空间 ⇒ 它只能测出下降、测不出提升（**天花板效应**）。  
四臂全部 `per_sample` **逐位相同** ⇒ 这支评测集**零区分度**，什么都证明不了。

⇒ **判据**：先算「与 `dense` 的**配对不一致对**数」。等于 0 ⇒ 这批数据**不能**用于任何比较。

### 铁律三：结论必须带着边界读

本机是 **CPU + 0.5B 模型 + 单卡**。报告中任何数字都**不能**外推到 GPU / 8B / 多卡。  
看到 `results/gpu/` 就想"有 GPU 结果"——先查里面的 `authoritative` 与 `device` 字段。

### H. 长文本的代价账（决定"能不能跑 32k"）

| 脚本                                  | 干什么                                        | 期望                          |
| ----------------------------------- | ------------------------------------------ | --------------------------- |
| `probe_long_context_cost.py [模型目录]` | 实测 1k/2k/4k/8k/16k/32k 的 dense 与 hook 单条耗时 | 16k/32k **内存不足**；4k 是甜点     |
| `measure_split_memory.py [模型目录]`    | 切分省内存的**解析账** + 与实测 OOM 报错对齐               | S=16384 → `9,663,676,416 B` |

**关键实测**（SmolLM2-135M，CPU，单条）：

| token | dense                                                             | hook   | 比值    |
| ----- | ----------------------------------------------------------------- | ------ | ----- |
| 1024  | 1.5s                                                              | 18.8s  | 12.4× |
| 4096  | 11.1s                                                             | 55.4s  | 5.0×  |
| 8192  | 81.3s                                                             | 191.0s | 2.4×  |
| 16384 | ❌ OOM：`not enough memory: you tried to allocate 9663676416 bytes` | —      | —     |
| 32768 | ❌ OOM：`you tried to allocate 34122217284 bytes`                   | —      | —     |

**最硬的一条**：`measure_split_memory.py` 用解析式算 S=16384 得 **9,663,676,416 B**，  
与 OOM 报错**逐位相同** ⇒ 这笔账是可信的，不是估算。

⇒ **结论：切分不是优化，是可行性前提**（32k 单卡物理装不下）。

⚠️ 别写"Qwen 支持 32k 所以能跑 32k"——`max_position_embeddings=32768` 只是**名义上限**，  
真实约束是**内存 `O(S²)`**。

## 7. 已知坑（我踩过的，逐条给"症状 → 原因 → 对策"）

**1. 所有命令 `command not found`（exit 127）**  
→ PATH 残缺，**不是 Git Bash 的固有缺陷**。  
→ 对策：命令开头补 §1.0 那句 `export PATH=...`。

**2. 反斜杠路径被吞掉**  
→ `C:\Users\...\python.exe` 报 `command not found`。  
→ 对策：**一律用正斜杠 + 双引号**：`"C:/Users/29914/.../python.exe"`。

**3. `cd` 也会被挡（看起来像"命令没输出"）**  
→ shim 报 `dirname: command not found`，**stdout 为空**，整条链没跑。  
→ 对策：先补 PATH（首选），或彻底不 `cd`——用 `git -C <绝对路径>`，  
或 `subprocess.run(..., cwd=<绝对路径>)`。

**4. 下模型拿到 0 字节空文件**  
→ 代理（`http://127.0.0.1:60155`）让 `huggingface_hub` 拿到空 body，  
报 `OSError: config file ... is not a valid JSON file`。  
→ 对策：**只用 `fetch_real_model.py`**（urllib 显式绕代理 + 校验字节数）。  
取日期同理，用 `date` 不要手算。

**5. 臂名标着"压缩"但准确率虚高**  
→ `compaction_mode="identity"` = **裁剪策略恒等 ⇒ 什么都不裁**，  
**不是**"不启用压缩"。有效模式只有 `topk_rms` / `topk_norm` / `random` / `stride`。  
→ 对策：**看 `compression_attestation.actually_cut`**（§4-J）。

**6. `prompt_tokens=1661~` 这类打印不是 token 数**  
→ `niah_eval.py` 里是 `len(s.prompt) // 4`，**字符数粗估**，不是 tokenizer 真值。  
→ 对策：要真 token 数就用 `AutoTokenizer` 自己 encode；  
`e2e_long4k.py` 印的 `实际 prompt 长度（token）` 才是真值。

**7. 长跑看不到进度、以为卡死**  
→ Python 的 stdout 是**块缓冲**：重定向到文件时不按行刷新，日志会一直很小  
（实测某次 12 分钟日志只有 1284 字节）。**这不是卡住。**  
→ 对策：① 用 `python -u` 关缓冲；② **别用 `... | tail -N` 判断进度**  
（`tail` 会等进程结束，中间什么都不给你看）；  
③ 长跑**写日志文件**再定期 `cat`：`> _out/xxx.log 2>&1`。

**8. 大面积 pytest `ERROR at setup`（像代码回归，其实不是）**  
→ 本机 `sitecustomize.py` 的删除守卫，**同回合**删除累计越阈值后进入拒绝态，  
连带打坏**无关的** `tmp_path` 清理。  
→ 自证：用数字恒等式对账（总数对得上 ⇒ 环境问题）。  
→ 对策：**跑测试与批量清理不同回合**。

**9. 后台任务句柄跨会话失效**  
→ 换个会话回来，`task_id` 已失效。  
→ 对策：**看落盘产物**（`_out/*.json`）判断完成，别依赖句柄。

**10. 16k/32k 直接 OOM**  
→ 不是"慢"，是单卡**物理装不下**（SDPA 是 `O(S²)`）。  
→ 对策：切分，或选 ≤8k 档。

**11. `git stash` 毁仓库（**&#x7EDD;对禁&#x7528;**）**  
→ 本项目实测事故：`git stash push -- <path>` 会丢 `refs/heads/<branch>`、  
清空对象库（`.git` 从 670 KB 掉到 240 KB）。  
→ 对策：**永不使用**。要临时换回旧版本文件做对照，用  
`git show HEAD:<path>` 取出内容到临时文件 → 覆盖 → 测完还原。

**12. `echo $?` 拿到的是管道的退出码**  
→ `python a.py | tail -5; echo $?` 给的是 `tail` 的状态（恒为 0）。  
→ 对策：不接管道，或用 `${PIPESTATUS[0]}`。
