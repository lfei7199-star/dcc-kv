## 第 2 页｜链路跑通（无 GPU）

**一句话**：真权重 + 真长文本 + 真切分，在 CPU 上端到端跑通。

**配置**：CPU（无 CUDA）｜真预训练权重 ｜ float32

**4k token 长文本结果**（Qwen2.5-0.5B，token 数精确构造 `[4096, 4096, 4095, 4096]`）

| 臂 | 准确率 | 耗时 |
|---|---|---|
| `dense`（不压缩基线） | 1.0000 | 126.1 s |
| `hook_dcc_W2`（源端切 2 段） | **1.0000** | 216.7 s |
| `hook_dcc_W4`（源端切 4 段） | **1.0000** | 214.3 s |

**两个亮点（建议做成两个小卡片）**

1. **跨族零改动挂载** —— 原以为要写适配器，实测**未改一行代码**即挂上 `Qwen2Attention`。
   （`arch=Qwen2ForCausalLM`，24 层，kv_heads=2，heads=14）
2. **切分是可行性前提，不是优化** —— 32k 单卡装不下（实测 OOM 报 **31.8 GB**），
   切 8 片后每片仅 **604 MB**。注意力矩阵 O(S²) ⇒ 切分省 **W² 倍**。
   *可信度来源：解析式与实测 OOM 报错**逐位相同**（`9,663,676,416 B @ S=16384`）。*

> ⚠️ **本页红线**（引用时必须带上）：
> - 四臂全对是**天花板效应**，**不能**读成"压缩不掉精度"；
> - 耗时含实现差距（dense 走融合核、hook 走显式核），**禁止**当性能数字引用。

## 第 3 页｜评测判据（本阶段技术含量最高的一页）

**一句话**：原来的评测集**测不出差异**，重建后测出来了，并把判据固化成了代码。

### 3.1 起点：发现旧评测集是"瞎的"

```
参照臂准确率 = 1.0000   ← 已满分，测不出提升
配对不一致对 = 0        ← 配对检验功效为零
```

⇒ 只能支持"跑通"，**不能**支持"精度不降"。**这就是"全 1.0 不是无损"的意思。**

### 3.2 重建后：NIAH n=20（**建议做成柱状图**）

| 臂 | 准确率 |
|---|---|
| `dense` | **1.0000** |
| `stride_0.25` | **1.0000** |
| `rand_0.25` | 0.9500 |
| `topk_0.5` | 0.4500 |
| `topk_0.25` | **0.2500** |

配对 McNemar：`topk` vs `rand/stride` **b=0、c=14/15、p=0.0001**。

**建议做的图**：柱状图，`dense`/`stride` 用**灰色**（基线），`rand` 用**橙色**（接近基线），
`topk` 两档用**红色**（劣化）。**不要**用绿色表示"好"。

**图旁配一句**：`b=0` 意味着 **20 条里没有任何一条出现「topk 答对而 rand/stride 答错」**。

### 3.3 高亮：真裁 4× 却零损失（**本页最亮的点**）

| 臂 | 裁前 | 裁后 | 真裁了吗 |
|---|---|---|---|
| `stride_0.25` | 768 | **192** | ✅ 是 |
| `rand_0.25` | 768 | 192 | ✅ 是 |
| `topk_0.25` | 768 | 192 | ✅ 是 |

⇒ **`stride_0.25` 真裁掉 576/768（4×），仍 20/20 全对。**
"压缩可以无损"在**别用 topk** 的前提下成立。

> 💡 为什么列"真裁了吗"这一列：因为"满分"最可能是**根本没压**，
> 所以每个压缩臂都**独立复算过 cache 实际长度**。这一列传递的是"我们验证过自己没作弊"。

### 3.4 判据落成

| 项 | 内容 |
|---|---|
| 判据 | **不一致对 > 0 且（方向不对称 或 参照臂两端有余量）** |
| 实现 | `experiments/common/discrimination.py`（418 行，单一事实源） |
| 锚点 | `tests/test_discrimination.py`（29 项，全过） |
| 全库回归 | **525 项通过，零失败** |

> ⚠️ **本页红线**：NIAH 结论**仅在本探针、本模型（0.5B）、本预算档上成立**，不可外推。

## 第 4 页｜边界与下一步

**一句话**：本阶段证明的是"测得出"，不是"效果好"；下一步卡在一件事上。

### 4.1 可主张 vs 不可主张（建议做成左右两栏对比）

| ✅ 可主张 | ❌ 不可主张 |
|---|---|
| 真权重 4k 链路跑通 | 任务质量 |
| 跨族零改动挂载（0.5B 内） | 通信性能 / 加速比 |
| 切分省 W² 内存（解析+实测一致） | 多卡可扩展性 |
| 评测集区分度 0 → 10 | 与基线的对比 |
| 量具判据落成 | — |

### 4.2 硬边界（一句话，别展开）

**核心质量主张 H2（相对共享压缩 ≥1.5pp）本机结构上测不出** ——
单卡模拟下所有源段看到同一批 query，`dcc_kv` 与共享压缩**数值不可区分**
⇒ 质量差**恒 ≈ 0**。**必须真多卡，给多少时间都测不出来。**

*（有代码守卫：`attention_hook.py:574` 硬编码 `False`；锚点测试 `test_attention_hook.py:333`）*

### 4.3 下一步（按依赖顺序）

1. **拿到 ≥2 张 GPU** → 跑真多卡对照行（**在此之前第 2、3 步做了也没用**）
2. 声明两个统计参数（非劣边界、噪声底线）
3. 补干净对照臂（`blockwise_no_compression`）

### 4.4 必须提的一句：一条自我纠正

> n=8 时观察到"LongBench 上 `topk` 优于 `rand`"（与 NIAH 相反），当时写成本节最重要结论；
> **扩到 n=20 后该翻转消失**（0.300 vs 0.250，p=1.0000）⇒ 那是小编号噪声。
> 旧报告**原文保留 + 加修正标记**，未删。

**建议放一句旁白**：「`arm ≈ 基线` 有两种成因 —— 操作真无害，或**仪器分辨不出**；
判据是看方向是否单向。」
