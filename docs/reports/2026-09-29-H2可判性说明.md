# DCC-KV：H2 质量主张（相对 kv_budget_shared ≥ 1.5pp）的可判性说明

> 生成日期：2026-09-29
> 判据来源：`experiments/common/hypotheses.py` — `H2_MIN_QUALITY_GAIN_PP = 1.5`
> 检查脚本：`_onetime_scripts/h2_blockers_check.py`（只读，可复跑，退出码 1 = 有未通过项）

---

## 一、结论先行

**H2 的「质量提升 ≥ 1.5pp」这一条，在当前硬件与配置下不可判定。**

原因不是"还没跑"，而是**当前配置下这两个量在结构上就是同一个东西**：

- `dcc_kv` 当前的运行方式是把源序列切成 W 段，在**单进程 / 单卡**内模拟 W 个源端设备。
- 「逐边条件化」的边际价值来自**每条边看到的目的端 query 不同**。
- 单卡模拟下所有源段看到的是**同一批** query ⇒ `dcc_kv` 与 `kv_budget_shared`
  在数值上**不可区分** ⇒ `Q_DCC − Q_shared ≈ 0` ⇒ **1.5pp 不可能出现**。

这条不是推断，是仓库自身的声明，有代码守卫：

| 位置 | 内容 |
|---|---|
| `src/distributed/attention_hook.py` 模块文档第 9 条 | 「单卡下所有段看到的是同一批 query，因此 `dcc_world > 1` 与『共享压缩』在数值上**仍不可区分**」 |
| `attention_hook.py:574` | `state.summary()["conditionalization_marginal_available"] = False`（硬编码 + 原因） |
| `tests/test_attention_hook.py:333` | `assert st.summary()["conditionalization_marginal_available"] is False`（锚点测试） |
| `experiments/gpu/e6_main_table.py:187` | 列为 `dcc_kv` 的 blocker |

## 二、H2 是三条同时成立，不是一条线

`hypotheses.h2_pass`：

```python
return bool(
    quality_comparable                              # ① 前提：与 dense 非劣
    and quality_gain_pp >= 1.5                      # ② 相对 shared 的提升（目标）
    and prefill_speedup >= 1.10                     # ③ 同核 prefill 加速
)
```

三条各自的现状（由 `h2_blockers_check.py` 实测）：

| # | 合取项 | 阈值 | 量具/链路 | 缺什么 | 结构上可测吗 |
|---|---|---|---|---|---|
| ② | `quality_gain_pp` | ≥ 1.5 pp | ✅ 链路已闭合 | **真实多设备路径** | ❌ **单卡下恒 ≈ 0** |
| ③ | `prefill_speedup` | ≥ 1.10× | ✅ H0 已接（`PREFILL_TIMING_CONSUMES_COMPACT_KV = True`） | 真权重 + 真实运行 | ✅ 是 |
| ① | `quality_comparable` | `CI_low > −delta` | ✅ 链路已闭合（先验键再算 CI） | `--h2-delta-pp` + `--h2-noise-floor-pp` | ✅ 是（需一次重复 run 测噪声） |

**注意区分「结构性不可测」与「暂时缺数据」**：

- 第 ③ 条：量具就位，**只缺跑一次**。给卡就能出数。
- 第 ① 条：判定程序就位，**只缺两个参数**。给参数就能判。
- 第 ② 条：**缺的是前提条件本身**。不给真多卡，它恒为 0，给多少时间都测不出来。

## 三、要判 H2，必须先满足的三个条件

### 条件 A：真实多设备路径（**这是硬门槛**）

- ≥ 2 张 GPU
- `--ranks > 1`，且 `dist.init_process_group` 起真进程组

`e6_main_table.py` 对"声称多卡"有闸门（文件头 `sync_axis_applies`）：

```python
sync_axis_applies(method, a) = (gpu_required > 1) and (--ranks > 1)
```

**声称 `--ranks > 1` 时脚本会检查进程组，没真的起多进程就直接以闸门退出码拒绝。**
这条设计是为了防止"声明多卡、实际单卡"把轴凭空造出来——同一个纪律也保护了 H2。

### 条件 B：真实预训练权重

模型清单（论文 §6 已写死，非待选）：

| 模型 | 用途 |
|---|---|
| `meta-llama/Llama-3.1-8B-Instruct` | 规模迁移 |
| `meta-llama/Llama-3.1-70B-Instruct` | 规模迁移 |
| `Qwen/Qwen2.5-72B-Instruct` | 跨族迁移（**需薄适配器**） |
| `mistralai/Mistral-7B-Instruct-v0.3` | 跨族迁移 |

### 条件 C：两个统计参数

```bash
--h2-delta-pp        # 非劣边界（允许比 dense 差多少，单位 pp）
--h2-noise-floor-pp  # 同一配置重复 run 的噪声底线
```

约束（`quality_comparable_non_inferior` 会 `raise ValueError` 拒绝执行）：

```
noise_floor_pp <= delta_pp < min(1.5, delta_bad_pp)
```

即：容差不得小于噪声（否则测不出差异 ≠ 确实无差异），也不得大于所要检测的效应量
（否则前提会把 H2 声称的 1.5pp 提升一并吞没）。

## 五、证据边界（必须与主张同时声明）

1. **本说明不主张任何任务质量结论。** 它只说明"该结论当前不可判"及其原因。
2. **`results/gpu/` 只有 `e8_cpu_reduced`**：`authoritative: false`、`device: "cpu"`。
   目前拿不出任何真实 GPU 产物。
3. **单卡模拟下 `dcc_kv` 与共享压缩数值不可区分** ⇒ 不能用单卡结果声称
   "条件化有效"或"条件化无效"——两个方向都不行。
4. **压缩机制（选键 / β 系数 / V 回归）源自 MIT CSAIL Attention Matching
   (arXiv 2602.16284)，非本项目原创。** 本项目原创的是异步 All-to-Allv 与
   顺序无关 Online Softmax 归并。对外说明须声明。
5. **`fastkv_official` / `ring` / `apb` 三个基线被阻断**（`--plan` 输出 3/6 被阻断），
   不能在论文中声称"已与它们对比"。

## 六、那现在能主张什么

在**不触碰 H2 质量主张**的前提下，以下几条有落盘证据、可以主张：

| 可以主张 | 证据 | 落盘位置 |
|---|---|---|
| 真模型 + 真注意力类上链路跑通 | tiny Llama、682 token 长文本切分、目的端条件化、紧凑 KV，CPU 跑通，`n_builds=8` | `_onetime_scripts/_probe_real_model_hook.py` |
| 切分→多进程→归并机制可跑 | 真 `mp.spawn` ×7、`gloo` ×10、变长 `all_to_all_v` | `tests/test_phase_a.py` |
| 归并数学正确 | 隔离对照误差 ≈ 3e-7，不随 N 累积 | `results/cpu/e4/*` |
| 切分本身几乎不掉精度 | 同上 | `results/cpu/e4/*` |

**不能主张**：任务质量、通信性能、多卡可扩展性、与基线的对比（README 层面的原有约束）。
